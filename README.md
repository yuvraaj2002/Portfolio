# Yuvraj Singh — Portfolio

A static portfolio built from `DESIGN.md`, the six supplied project knowledge bases, and user-provided experience descriptions. The visual system uses white, black, and grayscale only, including the profile photograph.

## Run locally

```sh
cd portfolio
npm run dev
```

Open http://127.0.0.1:3000. Python 3 and Node.js are sufficient; no dependency installation is required. `npm run check` checks JavaScript syntax, generated pages, local links, content escaping, project filters, and the grayscale palette.

## Content and editing

- `portfolio/index.html`: biography, page structure, and contact destinations.
- `portfolio/content.js`: six technical projects and a user-supplied MaxVal experience case study.
- `portfolio/styles.css`: responsive layout, monochrome tokens, and motion.
- `portfolio/app.js`: filtering, case-study links, and progressive scroll reveals.
- `portfolio/case-studies.cjs`: minimal public role and contribution summaries.
- `portfolio/publication-policy.cjs`: guards against reintroducing implementation fields and restricted details.
- `portfolio/build-case-studies.cjs`: dependency-free static page generator.
- `portfolio/work/<project-id>/index.html`: seven complete case-study pages, readable without JavaScript.
- `portfolio/CONTENT_SOURCES.md`: project provenance and claim limitations.

Employment descriptions indicate work domains rather than verified formal job titles. LinkedIn's public index confirmed Relecura and Chandigarh University; previous titles and employment dates were not accessible. The complete history links to the supplied LinkedIn profile. No employment dates or prior employers were inferred from third-party directories.

`DESIGN.md` describes another product. Its restraint, sans-serif typography, visible mobile navigation, focus treatment, and reduced-motion principles are adapted here; its product-specific agents, branding, and colors are not used.

## Static hosting

Only deploy `portfolio/dist/`, generated by `npm run build`. The build copies an explicit allowlist of runtime files and seven public work pages. Never deploy the workspace root or the `portfolio/` source directory. Resources, provenance notes, tests, build scripts, and policy checks are not included in the published artifact. The dev command also builds and serves `dist/`.

After changing project details, rebuild and verify:

```sh
cd portfolio
npm run build
npm run check
```

Each card opens a real directory-based URL such as `/work/patent-classification/`. Static hosts can serve or refresh those URLs without SPA rewrite rules. Pages include chapter navigation and next-project links. Return links include the category query parameter, so the homepage restores the corresponding filter. The pages contain concise, manually curated contribution summaries, not implementation walkthroughs. The generator does not read or render Resources Markdown. MaxVal is a role overview based on the description supplied by the user, rather than a fabricated technical project.

No analytics, remote fonts, trackers, or contact-form backend are used. Contact links open the supplied LinkedIn, X, and GitHub profiles. Company implementation and deployment details are intentionally omitted from public content.

Smooth scrolling uses a locally vendored Lenis 1.3.27 distribution in `portfolio/vendor/`, including its MIT license. `smooth-scroll.js` adds wheel easing and anchor navigation, keeps touch native, pauses background scrolling during case studies, and disables Lenis when reduced motion is requested. No installation or CDN request is needed to run the site. The build includes its runtime files automatically.

The GitHub contribution calendar is a remotely loaded, monochrome image served by [GitHub Chart API](https://github.com/2016rshah/githubchart-api), not by GitHub itself. It needs network access and may reflect provider caching. If unavailable, the site shows a fallback message and keeps the direct GitHub profile link available. It does not fabricate contribution data or infer productivity from the calendar.
